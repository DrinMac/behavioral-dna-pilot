# One-Week Free Deployment: Render + Neon

This is the simplest deployment path for the included package as of July 2026.

## Why this pairing

- Render can build and run the included Dockerfile as a public HTTPS web service.
- Neon provides a durable PostgreSQL connection independent of the web service filesystem.
- The Render blueprint is set to the Singapore region for lower latency from the Philippines.
- The application automatically accepts standard Neon PostgreSQL connection strings.

## 1. Create the PostgreSQL database

1. Create a Neon account and a Free-plan project.
2. Open the project's connection details.
3. Copy the pooled PostgreSQL connection string.
4. Keep `sslmode=require` or the SSL settings provided by Neon.
5. Save this value as `DATABASE_URL` when Render asks for it.

Do not use a SQLite database for the cloud deployment because a free web service's local filesystem may be replaced or reset. SQLite remains appropriate for local piloting.

## 2. Put the source in a Git repository

From the project folder:

```bash
git init
git add .
git commit -m "Deploy Behavioral DNA study"
git branch -M main
git remote add origin <your-repository-address>
git push -u origin main
```

Use a private repository when permitted by your hosting plan and institutional policy. Never commit `.env`, database files, exported participant data, or real secrets.

## 3. Create the Render service

1. Sign in to Render.
2. Choose **New Blueprint**.
3. Connect the repository containing `render.yaml`.
4. Render will detect the Docker web service.
5. Enter the values requested for variables marked `sync: false`:
   - `RESEARCHER_PASSWORD`
   - `DATABASE_URL`
   - `STUDY_CONTACT`
6. `SECRET_KEY` is generated by Render from the blueprint.
7. Confirm the service is using the Singapore region.
8. Deploy the blueprint.

## 4. Validate the deployment

After deployment, open:

```text
https://<your-service>.onrender.com/api/health
```

Expected response:

```json
{"status":"ok","participants":0,"sessions":0}
```

Then test:

- Participant page: `https://<your-service>.onrender.com/`
- Researcher page: `https://<your-service>.onrender.com/researcher`

## 5. Conduct a prelaunch pilot

Before sharing the link:

1. Register two test participants using different browsers.
2. Complete at least three sessions for one participant and one session for another.
3. Confirm automatic same-browser recognition.
4. Confirm manual recovery using `DNA-XXXXX` and the recovery PIN.
5. Build a baseline from the first participant's Sessions 1–2.
6. Evaluate the same participant's Session 3 and the other participant's Session 1.
7. Download and inspect the ZIP export.
8. Delete test records by creating a fresh Neon project or database before real collection.

## 6. One-week operating discipline

- Open the researcher dashboard at least daily.
- Download a data export every day and store it securely.
- Record the deployed Git commit hash and environment configuration.
- Do not change metric equations, prompts, thresholds, or baseline/test rules after final data collection begins.
- Export all data immediately after the collection window closes.
- Keep the cloud project only for the retention period approved by the study protocol.

## Free-tier cautions

- A free web service may sleep after inactivity, so the first participant after a quiet period can experience a cold start.
- Free database storage is limited. Monitor the database dashboard during recruitment, especially if the study enrolls many participants or collects more than ten sessions each.
- Free services are suitable for a short research pilot, not a production authentication service.
- Hosting platforms can maintain operational access logs even though this application does not intentionally store participant IP addresses.
